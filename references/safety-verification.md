# 安全执行与验证

## 风险分级

### 无外部副作用

纯单元、合同、解析、临时文件、mock 客户端和本地隔离服务可作为默认回归。

### 可回收副作用

测试数据库记录、测试账号草稿、临时对象等需要记录所有权和清理 ID。只有能确认归属时才自动清理。

### 高风险副作用

公开发布、付款、发送邮件/短信、推送通知、修改生产数据、删除内容、触发审核等必须获得用户本轮明确授权。执行前说明对象、数量和即时/定时性质。

## 验证顺序

1. 静态检查、导入和测试收集。
2. 最窄相关单元/合同测试。
3. 完整无副作用回归。
4. 检查日志和报告敏感信息。
5. 检查无残留端口、进程和临时资源。
6. 获得授权后执行一条最小真实流程。
7. 根据真实结果决定是否扩展场景，不自动连跑高风险案例。

## 执行前检查

- 目标环境、账号和数据明确。
- 测试数据存在且合规。
- 只有授权案例启用。
- 超时和停止条件明确。
- 能区分成功、明确失败和结果未知。
- 报告与日志已脱敏并被版本控制忽略。

## 真实成功证据

不要仅以进程退出码、点击完成、请求发出或 HTTP 200 判断业务成功。根据系统选择组合证据：

- 最终业务状态码。
- 创建资源/发布/订单/任务 ID。
- 期望状态迁移完整。
- 数据库或查询接口可见的最终状态。
- UI 与后端一致。
- 没有失败原因，清理状态符合预期。

## 停止条件

以下情况停止，不自动重试：

- 可能已经完成副作用，但最终响应丢失。
- 平台限流、安全验证、账号异常或审核拒绝。
- 启用案例数量超过用户授权。
- 无法可靠过滤敏感信息。
- 清理目标归属不明确。
- 测试要求开始依赖修改生产逻辑才能“通过”。

重试可能重复创建、收费或通知。必须确认第一次没有提交并重新获得授权。

## 交付摘要

报告：

- 修改的文件和测试结构。
- 覆盖的需求和层级。
- 实际执行命令与结果数量。
- 外部副作用是否执行及脱敏资源 ID。
- 报告路径。
- 未执行项、环境限制和剩余风险。
